# ТЗ мобильного приложения

## Карта экранов

| Экран | API operationId | Логики |
|---|---|---|
| Список тренировок | `listSlots` | LOGIC-002, LOGIC-005, LOGIC-008 |
| Карточка тренировки | `getSlot` | LOGIC-002, LOGIC-003, LOGIC-006, LOGIC-008 |
| Форма записи | `createBooking` | LOGIC-002, LOGIC-003, LOGIC-008 |
| Мои записи | `listBookings` | LOGIC-004, LOGIC-008 |
| Детали записи | `getBooking`, `cancelBooking` | LOGIC-004, LOGIC-008 |

## Принцип

Числа и ограничения не хардкодятся в UI: цена, лимиты, свободные места, доступный прокат и статусы приходят из API. Клиент может валидировать форму до отправки, но финальное решение принимает backend.

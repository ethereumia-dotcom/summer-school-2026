# Шаг 0. Вход — бриф заказчика

## Исходный заказчик

Оля, владелица скалодрома «Вертикаль».

## Сырая проблема

Запись на тренировки ведётся вручную в Telegram и тетрадке. Из-за ручного процесса возникают:

- двойные записи на одно место;
- путаница со свободными местами и инструктором;
- отсутствие единого источника расписания для клиента;
- сложность с отменами и массовым оповещением.

## Базовый процесс

- Скалодром проводит групповые тренировки длительностью около 1,5 часов.
- Форматы: болдеринг с инструктажем для новичков и трассы с верёвкой для опытных.
- Каждую тренировку ведёт инструктор.
- Расписание формируется на неделю вперёд.
- В группе до 16 человек, но для новичковых тренировок максимум 8.
- Клиент должен видеть свободные слоты и записываться сам.
- При записи клиент выбирает своё или прокатное снаряжение.

## Зафиксированные уточнения скоупа

- Текущая поставка — только клиентское мобильное приложение и API для него.
- Backend, хранение данных, админка и интерфейс инструктора уже существуют.
- Клиент не создаёт и не редактирует расписание, зоны/форматы и инструкторов.
- Backend — black-box источник истины, гарантия «0 двойных броней» находится на его стороне.
- Каноническая схема данных — API-контракт.
- По умолчанию показываются слоты на ближайшие 7 дней.
- Отмена скалодромом отображается у клиента статусом «Отменена скалодромом», запись не удаляется.

## Что нельзя напрямую превращать в MVP без уточнений

- онлайн-оплата;
- программа лояльности;
- публичный рейтинг инструкторов;
- админский экран расписания;
- интерфейс инструктора;
- автоматизация профилактики и отмены тренировок со стороны клиента.

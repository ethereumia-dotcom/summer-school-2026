# F-002. Фильтры тренировок

## Цель

Дать клиенту возможность быстрее найти подходящую тренировку по предустановленному периоду, формату, инструктору и доступности мест.

## Требования

- FR-003–FR-006: клиент фильтрует тренировки по датам, формату, инструктору и наличию мест.
- Клиентское приложение не создаёт и не редактирует расписание, а только читает слоты из API.
- Слоты, форматы и инструкторы поступают из существующего backend.

## Что сделано

- Оставлен существующий bottom sheet фильтров.
- Проверена связка `SlotListScreen` → `SlotListStore` → `SlotRepository`.
- Фильтры применяются после нажатия «Применить».
- Сброс фильтров возвращает MVP-дефолт 7 дней.
- Preset периода переименован в UI с «Эта неделя» на «7 дней», чтобы не путать календарную неделю и ближайшие 7 дней.
- Тексты экрана адаптированы под скалодром: «Тренировки», «Пока нет доступных тренировок».

## Использованные промпты

1. «Найди в Compose Multiplatform клиенте экран списка слотов и опиши, как устроены фильтры».
2. «Проверь, какие фильтры уже поддерживаются API-контрактом и как они маппятся в query params».
3. «Адаптируй пользовательские тексты фильтров и списка под бриф “Скалодром” без изменения backend».

## Ручная проверка

- Открыл экран «Тренировки».
- Открыл фильтры.
- Выбрал период, формат, инструктора и «Только со свободными местами».
- Нажал «Применить».
- Убедился, что список обновился.
- Проверил состояние «Нет слотов по условиям».

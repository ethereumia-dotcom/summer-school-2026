# Non-functional requirements

| ID | Требование | Приоритет | Источник |
|---|---|---|---|
| NFR-001 | Интерфейс должен быть удобен с телефона | Must | письмо заказчика |
| NFR-002 | Состояния loading/error/empty/success должны быть явно описаны для каждого экрана | Must | материалы лекции |
| NFR-003 | Клиент должен корректно обрабатывать отказ backend без падения | Must | R-004 |
| NFR-004 | Accessibility: тексты и основные действия должны быть доступны для screen reader; контраст не ниже WCAG AA | Should | foundations |
| NFR-005 | Idempotency-Key используется при создании брони для защиты от повторной отправки | Should | R-004 |
| NFR-006 | Детали SLA, транзакционности и внутреннего маппинга backend вне скоупа клиента | Must | R-004 |

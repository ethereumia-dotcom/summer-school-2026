# Functional requirements

| ID | Требование | Приоритет | Источник |
|---|---|---|---|
| FR-001 | Клиент видит список тренировок на ближайшие 7 дней по умолчанию | Must | R-027 |
| FR-002 | Клиент видит empty state «Пока нет доступных тренировок», если расписания нет | Must | R-027 |
| FR-003 | Клиент фильтрует слоты по датам | Must | бриф + R-027 |
| FR-004 | Клиент фильтрует слоты по формату тренировки | Should | бриф |
| FR-005 | Клиент фильтрует слоты по инструктору | Should | бриф |
| FR-006 | Клиент может включить фильтр «только со свободными местами» | Should | бриф |
| FR-007 | Клиент открывает карточку доступной тренировки | Must | бриф |
| FR-008 | Отменённый слот недоступен для повторной записи | Must | R-008 |
| FR-009 | Клиент создаёт бронь на слот | Must | бриф |
| FR-010 | Клиент указывает количество участников в рамках лимита API | Should | API-паттерн учебного проекта |
| FR-011 | Клиент выбирает своё или прокатное снаряжение | Must | бриф + R-015 |
| FR-012 | Приложение не даёт выбрать прокат сверх доступного фонда | Must | R-015 |
| FR-013 | Клиент видит итоговую цену с учётом проката | Should | R-015 |
| FR-014 | Клиент видит свои будущие, прошедшие и отменённые записи | Must | бриф |
| FR-015 | Клиент может отменить свою активную запись | Should | бриф |
| FR-016 | Клиент видит понятную ошибку, если backend отказал из-за отсутствия мест | Must | R-004 |
| FR-017 | Бронь, отменённая скалодромом, остаётся в списке с причиной | Must | R-008 |

## Out of scope / Phase 2

- FR-P2-001: онлайн-оплата;
- FR-P2-002: оценка инструктора после тренировки;
- FR-P2-003: программа лояльности;
- FR-P2-004: админский экран расписания;
- FR-P2-005: интерфейс инструктора;
- FR-P2-006: реальная push-интеграция и напоминания. В MVP клиент корректно отображает статус отмены, полученный из API.
